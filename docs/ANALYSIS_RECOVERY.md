# 분석 요청 중단 대응 · 2026-10-25

`사진 처리 요청이 실패했습니다`는 JSON 오류가 없는 응답의 공통 대체 문구였다. 이 문구만으로 결제 한도, 사진 손상, Cloudflare 실행 제한 중 무엇인지 단정할 수 없다. 분석 기록이 pending으로 남았다는 것도 공급자 요청 도달·과금·완료 여부를 확정하는 증거가 아니다.

브라우저는 HTML 등 비정상 응답에서 HTTP 상태를 표시하고, 1101·1102 같은 플랫폼 코드가 실제 응답에 있으면 별도 안내한다. 런타임 원인을 과거 로그에서 확인하지 못한 상태에서 CPU 제한으로 확정하지 않는다.

분석 POST의 응답 중단·네트워크 오류·JSON 손상 시 접근 권한이 있는 기존 job GET으로 저장 완료 여부를 확인한다. 완료된 현재 분석 버전이 확인되면 그 결과를 재사용한다. 확인되지 않으면 중복 과금 방지를 위해 POST를 자동 재시도하거나 다음 유료 요청으로 진행하지 않는다. 잠시 뒤 작업을 복구하고 AI 추천 다시 요청으로 미완료 사진을 처리한다. 정상 완료 사진의 버전·서명·추천은 변경하지 않는다.

원본 사진 GET만 일시 오류에 최대 두 번 재시도한다. 인증·접근 권한·명시적 자원 제한은 재시도하지 않는다. 공급자의 429나 기존 구조화된 전역 오류는 즉시 중단한다.

서버의 이미지 base64 인코딩을 바이트별 문자열 누적 대신 네이티브 toBase64 또는 청크 단위 변환으로 대체한다. 원본 바이트·AI 이미지 해상도·모델·분석 버전은 유지한다. 런타임 오류의 근본 원인이 이 연산이었다고 단정하지 않는다.

테스트: 대용량 인코딩의 바이트 일치(네이티브/대체), HTML 1102 뒤 저장 결과 복구, 미확정 응답에서 유료 POST 재호출 금지, 사진 GET 재시도, 기존 quota 중단, 전체 모바일 작업 흐름. 실제 공급자 호출은 수행하지 않는다.
