# 작업자 확정 사례 활용

작업자는 기존과 같이 내용을 확정합니다. 최종 작업명, AI 추천, 수정 여부는 비공개 `np_learning_feedback`에 저장합니다. 사진 한 장의 최신 상태를 유지하여 자동 저장마다 같은 기록을 중복 생성하지 않습니다.

로그인된 앱이 작업 복구·확정 저장·작업 종료 시 사본을 순차 등록합니다. 기존 작업 접근 권한을 그대로 검사하며 다른 기기의 사진을 조회할 수 없습니다. 대화 환경으로 사진을 내보내거나 공개 다운로드 주소를 만들지 않습니다.

참고 사본은 원본에서 기존 명판을 가린 960×720 이하 JPEG입니다. 복잡한 사진은 768×576으로 축소할 수 있으며 256KiB를 넘으면 이미지 추가를 건너뛰고 기록은 남깁니다. 전체 참고 사진은 기존 자료를 포함해 256MiB까지 보관합니다. 같은 원본 해시는 사본 하나만 재사용합니다. 캡처 자체는 유료 AI를 호출하지 않습니다.

표준 작업과 일치하는 확정 사례는 관리자 미검수임을 구분하여 다음 신규 분석에 참고합니다. 새 작업 문구는 관리자 검수 대기입니다. 같은 사진의 서로 다른 작업명은 충돌로 보류하고, 기존 검수 답안·평가용 자료를 자동으로 덮어쓰거나 추천용으로 전환하지 않습니다. 관리자가 제외한 사례는 재확정만으로 다시 활성화되지 않습니다.

관리자 → 기존 사진 OCR 검수·참고 자료 → 작업자 확정 필터에서 등록 상태를 확인합니다. '추천에서 제외'는 사진을 삭제하지 않고 검색에서 제외합니다. 새 작업명은 검수 완료 시 표준 목록에 추가됩니다.

원본·완성 사진은 기존의 저장 완료/24시간 삭제 정책을 따릅니다. 확정 기록과 등록 완료한 참고 사본은 별도로 유지합니다. 작업 종료 버튼은 참고 사본 전송을 먼저 기다립니다. 브라우저가 닫히면 전송이 멈추며 작업 만료 전 다음 접속에서 미등록 사본을 이어서 보냅니다. 만료·삭제 뒤의 원본 사진을 복원하는 기능은 아닙니다.

기존 설치는 `supabase/schema/worker-learning.sql`을 AI 스키마 다음에 적용합니다. RLS와 서비스 전용 RPC를 사용하며 프런트엔드에 관리 키가 필요하지 않습니다. `npm run test:learning`과 `npm run test:e2e`로 검증합니다. 테스트의 AI 응답은 모의 처리이며 실제 추천 정확도 향상을 측정했다는 뜻은 아닙니다.
