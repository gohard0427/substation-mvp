# 2026-10-17 참고 사진 일괄 등록 결과

## 실제 등록

- 입력: ZIP 19개, 약 483MiB, 사진 915개. 원본 경로와 출처를 보존했다.
- 동일 원본 6건을 감지했다. 원본 파일을 삭제하지 않고 해시당 한 검색 항목으로 연결했으며 중복 출처는 `ocr_raw.sourceOccurrences`에 기록했다.
- 앱 DB·비공개 스토리지: 909개 참고 항목 연결 완료. 기존 62개 초안은 이번 자료와 겹치므로 총계에 다시 더하지 않는다.
- 명판 없는 사진 11개를 별도로 표시했다. 이 사진들의 OCR 출력은 작업명 정답으로 사용하지 않는다.
- 로컬 Tesseract 한국어 OCR로 명판 원문과 정리된 값을 분리했다. 작은 비율 오차는 잘라내지 않고 여백으로 보존했다. 세로 명판은 별도 좌표로 대조했다.
- 원본 명판과 24개 항목의 공사명·위치·기기명·내용·일자를 화면으로 대조하고 OCR 오독을 수정했다. `CT`가 `07`로 읽힌 경우를 포함한다. 이 24개만 검수된 추천 참고 자료다.
- 나머지 885개는 검수 대기다. 자동 OCR 확신도를 관리자 검수로 간주하지 않는다.
- 작업 폴더별로 분리한 평가용 193개는 추천 검색에서 제외한다. 아직 정답 검수와 실제 추천 정확도 평가는 수행하지 않았다.
- 마스킹 참고 사본과 관리자용 명판 대조 이미지 등을 합해 약 77.7MiB를 사용했다. 참고 사본은 기존 비공개 100MiB 예산 안에 있다.

관리자 화면에서 **기존 사진 OCR 검수·참고 자료**를 열면 사진·원본 명판 대조·검색·검수 상태 필터를 사용할 수 있다. 기존 명판 대조용 ZIP 연결은 별도의 사진 수 한도 최대 2,000개를 지원하되 기존 ZIP 90MiB·압축 해제 150MiB 안전 한도는 유지한다. 일반 작업 업로드는 작업당 50개 제한을 그대로 유지한다. 이번 915개 등록은 관리용 분할 처리 경로로 수행했으며, 일반 사용자에게 대용량 ZIP 비동기 업로드 기능이 완성됐다는 의미가 아니다.

## 검증과 비용

- 모든 909개 항목은 이미지 연결 상태다. 남은 임시 업로드 예약은 0개다.
- 서버에서 12개 참고 사본을 다시 내려받아 로컬 사본 SHA-256과 일치함을 확인했다.
- 일회성 수입 권한은 2시간 만료 및 256비트 임의 토큰 해시로 보호했다. 완료 후 서버 권한을 제거하고 실제 HTTP 403 응답을 확인했다.
- 참조 사진·명판 이미지·실제 OCR 문구·토큰·원본 ZIP을 GitHub에 넣지 않았다.
- 이번 등록과 OCR 과정의 외부 유료 비전 API 호출은 0회다. 기존 앱 호출 20회와 구분한다.
- 다음 추론 시험을 위해 관리자 설정의 일일 호출 한도를 100회로 조정했다. 전체 시험 누적 100회 제한은 유지되어 현재 남은 새 호출은 최대 80회다. 승인 예산은 총 30,000원 이내이며, 호출 수 제한은 원화 결제액의 강제 상한과 다르다.
- `test:reference-import`는 무권한·만료 권한 차단, JPEG 검증, 비공개 등록·중복 재등록·검수 미확정 상태, 관리자만 명판 대조 이미지 접근, 권한 해제를 검사한다. 실제 PGlite를 사용하고 공급자 인증·스토리지는 모의 처리다.
- 실제 Chromium으로 검수 화면과 기존 ZIP 업로드·명판 생성·복구·다운로드를 검사했다. 실제 운영 사진에 대한 추천 정확도 시험은 별도로 해야 한다.

일괄 등록 중 명판 없는 원본의 잘못 추출된 미리보기 삭제·입력 초기화는 자동 승인 검토에서 거부됐다. 해당 동작은 실행하지 않았다. 대신 파일과 OCR 원문을 유지하고 명판 없음 표시만 추가했으며, 해당 미리보기는 화면과 명판 조회 API에서 숨겼다. 삭제 기능은 수입 경로 코드에도 포함하지 않는다.

보안 점검에서 서버 전용 표의 RLS 정책 없음 INFO는 직접 접근 권한을 차단한 설계다. 기존 유출 비밀번호 검사 비활성 WARN은 이번 작업에서 변경하지 않았다. [Supabase 설명](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)

## 관리용 일괄 수입 경로

`supabase/functions/np-reference-import/index.ts`는 내부 일괄 수입용이다. 브라우저 공용 계정 인증을 대체하지 않는다. `np_config.payload.referenceImport`에 서버 관리자가 유효한 `tokenHash`, `expiresAt`를 설정한 기간에만 별도의 임의 Bearer 토큰으로 호출할 수 있다. 기본 상태에서는 거부하며, 실제 서비스 키는 Edge Function 환경에서만 사용한다. 수입 요청은 512KiB, JPEG 규격·원본 해시·경로·라벨·특징 값을 검증한다. 기존 검수 라벨을 덮어쓰지 않으며 DB의 기존 100MiB 예약·확정·실패 정리 절차를 사용한다.

새 서버 수입은 권한 부여, 로컬 OCR 및 마스킹, 사진 단위 POST, 파일 재조회 검증, 권한 제거 순으로 수행한다. 토큰·원본 사진은 코드나 Git 커밋에 넣지 않는다. 관리자 계정과 비밀번호·세션을 임의로 만들지 않는다.
