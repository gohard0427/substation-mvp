# 기존 작업 분석을 추천에 적용

2026-10-20. 기존909장 분석에서 정리한126개 작업명의 가시 특징·구분 단서·한계를 서버의 `cloudflare/data/work-guides.json`과 `cloudflare/work-knowledge.mjs`에 반영했다. 사진·원본 경로·명판 개인정보는 코드에 넣지 않는다.

## 적용 흐름

1. 기존 장치별 작업 접근 권한으로 방향 보정·명판 마스킹이 일치하는 분석 사본을 받는다.
2. 신규 사진만으로 관찰과 최대3개 작업 후보를 얻는다. 단위·모드·대상과 판독 가능 여부를 구조화한다. 구분에 필요한 정보가 없으면 unknown 또는 빈 후보로 둔다.
3. 1차 후보와 같은 작업의 허용 참고 사진을 우선 고른다. 같은 작업 안에서는 기존 색상·공간 특징 순위로 대표 사례를 선택한다. 후보 작업 최대2종과 다른 작업1종을 대조한다. 평가·충돌·미검수 자료를 자동 정답으로 쓰지 않는다.
4. 사례가 있으면 같은 신규 사진과 명판을 가린 최대5개 사본, 해당 작업의 구분 기준을 비교해 최종 추천을 만든다. 사례가 없으면1차 결과를 사용한다.
5. 전압 모드에서 선명한 V, 저항 모드에서 선명한 Ω와 모순되는 후보를 서버에서도 제거한다. 절연저항계의 V 시험 설정값은 이 규칙을 적용하지 않는다. 판독 근거가 불명확하면 단위 규칙을 적용하지 않는다. 설비 타입에 맞는 필수 사용자 선택은 항상 유지한다.

이는 회사 데이터로 모델 가중치를 재학습한 기능이 아니다. CLIP 이미지 검색은 오프라인 가능성 시험만 수행했으며 이 배포에는 추론 서비스가 없으므로 사용하지 않는다. 본 검색을 CLIP·의미 임베딩 검색이라고 표시하지 않는다. 기존 색상 특징의 한계를 후보별 자료 선택으로 보완한다. 자동 확대 분석도 이번 배포에는 포함하지 않았다.

## 참고 자료 신뢰도

- `reviewed`:관리자 전체 검수.
- `worker_confirmed`:작업자 확정, 관리자 검수와 별도.
- `ocr_raw.workAudit`:명판의 작업명 행을 장면과 분리해 확인한 기록. 전체 기술적 정답/기기명 검수가 아니다.
- 명판의 세부 모순·정답 없음은 `blocked`로 보존한다. 사진 파일을 삭제하지 않는다.
- 명판 OCR·이전 라벨은 유지한다. 명백한 작업명 오독만 원본 해시·예상 이전 값으로 대조해 수정한다. 이미 관리자 검수·작업자 수정·제외한 값은 덮어쓰지 않는다.
- 후속 관리자 검수로 명시적으로 복구한 자료는 `adminOverride`로 표시하고 과거 일괄 적용으로 다시 차단하지 않는다.
- 평가용 분리를 유지한다. 이번 분석 자료를 설계에 사용했으므로 향후 정확도는 새 고정 평가 세트에서 검증해야 한다.

`reference-work-audit.sql`의 함수는 PUBLIC/anon/authenticated에 실행 권한이 없으며 서비스 역할만 호출한다. 기존 작업자/관리자 API가 전체 관리 키를 공개하지 않는다. 일반 작업자에게 참고 사진 DB를 공개하지 않는다.

## 호출·비용·캐시

사진당 최대2회 공급자 호출, 참고 사례가 없으면1회다. 첫 성공 결과/토큰을 먼저 서버에 기록하고 비교 결과와 합산한다. 비교가 실패하면1차 결과와 비교 실패 표시를 저장한다. 자동 유료 재시도는 없다. 비교 실패 결과도 캐시되므로 같은 조건의 재요청에 비용이 반복 발생하지 않는다. 모델·규칙·허용 참고 목록/갱신 시각·회전·타입/대상기기 맥락이 바뀌면 캐시가 무효화된다.

`np_ai_runs` 한 행은 사진 분석1건이며 `usage.api_calls`는 공급자 요청 시도 수다. 실패·연결 중단 공급자의 미보고 사용량은 알 수 없어 토큰 비용은 실제 청구서와 다를 수 있다. 서버의 기존 시험 제한 해제 설정은 변경하지 않는다.

기존 확정 사진은 자동 재분석하거나 내용을 바꾸지 않는다. 새 사진은 자동으로 새 규칙을 쓰며, 미확정 이전 버전 사진은 기존 AI 재요청 기능에서 처리한다. 작업자 화면은 늘리지 않는다. 관리자 참고 목록에서 작업명 대조·충돌 상태를 확인할 수 있다.


## 정확도 우선 보강 (2026-10-20)

`work-vision-v5-contrast`는 최근 작업자 확정에서 반복된 일반 점검↔저항/절연저항 혼동을 비교 대상으로 삼습니다. 1차 후보에 해당 작업이 없어도 관련 작업의 사례를 함께 비교하며, 기존 명판 대조 자료와 작업자 확정 사례를 구분합니다. 명확한 MΩ 절연저항 근거와 일반 저항/전압 후보의 충돌도 검사합니다. 미확인 단위에는 강제 필터를 적용하지 않습니다.

신규·참고 사진은 공급자 `detail:high`, GPT-5 계열은 `reasoning:medium`, 최대 출력은 6000토큰으로 요청합니다. 공급자 호출은 여전히 최대 두 번이며 참고 사진은 최대5개입니다. 더 많은 이미지 토큰과 추론이 시간·비용을 늘릴 수 있습니다. 병렬 처리·속도 단축은 이번 범위에 없습니다. 기존 65초 요청 제한과 실패 시 1차 결과 복구는 유지합니다. 모델의 확신도를 정확도처럼 표시하지 않습니다.

`supabase/schema/confirmed-work-expansion.sql`은 실제 확정 기록에 존재하는 명시적 회사 작업명만 표준 목록에 보충하고, 최신 확정 내용과 사본이 일치하는 작업자 참고 자료를 활성화합니다. 관리자 제외·작업명 충돌·평가용·오래된 확정 내용은 유지하며, 모호한 ‘축전기 설치 전’은 축전지로 임의 통합하지 않습니다. 모델 학습이나 관리자 전체 검수로 표시하지 않습니다. 향후 새 작업명을 무조건 자동 승인하지 않습니다.

참고용으로 활용한 최근 확정 사진을 별도 평가 정답으로 중복 사용하지 않습니다. 자동화 테스트는 검색/권한/필터/요청 구조를 검증하며, 실제 사진에 대한 유료 API 비교 평가를 수행하지 않았으므로 정답률 개선 수치를 주장하지 않습니다. 기존 확정 내용은 바뀌지 않고 새 사진 및 미확정 사진 재분석에 새 버전이 적용됩니다.
