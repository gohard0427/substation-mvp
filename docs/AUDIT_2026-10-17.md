# 전체 점검 기록 — 2026-10-17

점검 대상은 현재 운영 중인 **무료 Pages·Supabase 명판 앱**입니다. 별도 ‘작업자 명단’ 앱은 수정하지 않았습니다. 유료 비전 API 호출·플랜 업그레이드는 하지 않았습니다.

## 발견 후 수정한 내용

| 항목 | 수정 결과 |
|---|---|
| 자동 삭제 함수만 있고 실행 예약이 없었음 | 실제 Supabase pg_cron·pg_net 예약 설정. 운영 주기 15분. 전용 임의 토큰은 Vault에 보관하고 해시만 서버 전용 표에 저장. service_role 키를 cron 본문에 복사하지 않음 |
| 요청한 기본 공사명 미반영 | `2026~2026년도 시흥전력지사 변전협력회사 총액공사` 고정. 관리자가 추가 공사명 목록 등록, 작업자는 선택 또는 직접 입력. 작업별로 저장하고 생성 시작 시 고정해 다른 작업에 전파되지 않음 |
| 계정 전환용 로그아웃 없음 | 현재 앱 세션만 폐기. 기기 복구 쿠키는 유지해 재로그인 후 작업 복구 |
| 생성 중 다른 작업 열기·업로드 가능 | 처리 중 업로드·복구·작업 전환 차단. 생성 중지 기능은 유지 |
| 큰 ZIP의 중앙 항목 배열이 검사보다 먼저 만들어짐 | ZIP 끝 레코드의 항목 수를 먼저 확인. 2,000개 초과·분할·대용량 ZIP64·손상 끝 레코드 거절 |
| 오래된 한글 ZIP 파일명 깨질 가능성 | UTF-8 및 한국어 Windows CP949 이름 해석. 출력 이름은 대소문자 충돌 시에도 고유하게 만들어 Windows 덮어쓰기 방지 |
| 많은 사진·추천·경고의 정상 JSON이 작은 제한에 걸릴 수 있음 | 사진 메타데이터 512KiB, 경고 1.5MB로 제한을 분리해 명시적으로 검사 |
| 복구·다운로드가 마지막 활동 시각을 갱신하지 않음 | 명시적 복구·다운로드는 24시간 기한을 갱신. 자동 미리보기는 갱신하지 않고, 이미 만료된 작업은 복구하지 않음 |
| 삭제 실패 후 재접속하면 작업을 열 수 없음 | 삭제 중 목록에서 삭제 재시도 화면 복구. 파일 삭제 성공 전 예약 기록 제거 금지 유지 |
| 인증 공급자 장애도 비밀번호 오류처럼 보일 수 있음 | 비밀번호 실패·사용자 ID 불일치·API 설정·공급자 한도를 구분 |
| 관리자 참고 이미지 마스킹 때 큰 캔버스 생성 | 최대 긴 변 1280 작업용 크기로 줄인 후 마스킹해 모바일 메모리 부담 완화 |

정적 화면에 CSP를 적용하고 실제 브라우저에서 ZIP·폰트·다운로드가 차단되지 않는지 확인했습니다. 기존 Python 로컬 버전에는 새 무료 API 전용 메뉴를 숨겨 호환성을 유지합니다.

## 실행한 검사

총 **자동 테스트 68개 통과**: 무료 API 10, AI 모의 응답 5, 정리·로그아웃·공사명·만료 6, ZIP 4, 기존 Python 34, 저장 충돌 UI 3, 기존 릴레이 6. 추가로 실제 Chromium의 Canvas 검사와 전체 사용자 흐름 검사 2개를 통과했습니다.

- EXIF 방향 6을 넣은 JPEG의 방향 보정, 세로 사진 회전, 한글 폰트, 긴 기본 공사명, 최대 1280×960 JPEG, 가장 오른쪽·아래 테두리, 명판 마스킹·픽셀 특징을 확인.
- 모바일 폭 390 및 320px에서 가로 넘침 검사. 한글 ZIP 3장 업로드 → 손상 사진·지원 외 형식 안내 → 중복 보존 → PMA 선택 전 생성 차단 → 작업별 공사명 저장 → 첫 결과만 생성 → 탭 종료 → 복구·나머지 생성 → 실제 다운로드 ZIP을 다시 열어 경로·JPEG 크기·EXIF 제거 확인.
- 별도 브라우저 기기에서 작업 접근 차단, 작업자의 관리자 자료 접근 차단, 로그아웃 후 같은 기기 복구, 저장 완료 후 임시 파일 제거 확인.
- 관리자 참고 ZIP 연결 → 원본 명판 미리보기 → 검수 저장 → 평가용 분리 검사. 임시 작업 종료 시 참고 사진은 유지됨을 확인.
- 이 브라우저 검사에서 실제 JS·Canvas·HTTP API·PostgreSQL 호환 PGlite를 사용했지만 **외부 Auth·Storage·비전 응답은 테스트 대체 서버**입니다. 운영 클라우드 전체 사용자 흐름을 자동 로그인해 확인한 것은 아닙니다.

## 실제 운영 서버에서 확인한 내용

- 실제 Storage에 4×3 시험 JPEG를 업로드하고 읽은 뒤, 만료 정리로 **파일·파일 예약·작업 행 모두 삭제**되는 것을 확인. 정리 응답 `selfTest: {jobGone:true, fileGone:true, objectGone:true}`, HTTP 200.
- cron 예약 실행 2회 성공 및 실제 함수 HTTP 200을 확인한 뒤 운영 예약을 **15분**으로 확정. 관리자 화면에 최근 성공 시각 표시.
- 실제 사용자의 진행 중인 작업은 시험용 데이터와 분리. 시험 작업 잔여 0건 확인.
- 서버 전용 표·RPC의 anon/authenticated 직접 권한 차단 확인. 사진 버킷은 비공개.
- 점검 시 참고 OCR 초안 62건, 연결 이미지 0건, 검수 완료 0건, 실제 비전 호출 기록 0건. 참고 자료는 아직 사용자 연결·검수가 필요함.
- `npm audit --omit=dev`: 운영 npm 의존성의 알려진 취약점 0건. 모든 보안 문제의 부재를 뜻하지 않음.

## 남은 제한·후속 검증

- 실제 스마트폰 실기기와 Windows 압축 해제, A4 2열×3행 실물 인쇄 가독성은 미검증. 브라우저 JPEG 품질 인자는 0.85이지만 브라우저별 인코더 결과는 다를 수 있음.
- 작업당 50장·ZIP 90MiB·압축 해제 150MiB·사진 8MiB·2천만 픽셀 제한. 화면을 닫으면 업로드·합성은 중지되고 완료 사진부터 이어서 처리. 월간 1,000장 서버 백그라운드 처리는 미구현.
- 명판 생성은 방향 보정 후 가로 320px 미만 이미지를 거절하며 작은 원본을 확대하지 않음. 이미지 비율이 다르면 여백으로 보존. 명판은 측정한 대표 프로필 하나를 적용하고 원본 글꼴 완전 일치·다른 프로필 자동 선택은 미지원.
- 참고 사진 연결·OCR 검수와 실제 AI 추천 정확도·사진당 실비 측정은 남아 있음. 현재 검색은 저수준 색상·공간 밝기 특징이며 의미적 이미지 임베딩이 아님. 유료 모델을 연결하기 전에 검수와 평가 자료를 확보해야 함.
- 서버 정리는 15분 간격이며 호출당 최대 500개 파일을 처리. 장애·무료 프로젝트 일시 중지·삭제 적체 시 삭제가 지연될 수 있음. 만료된 작업의 API 접근은 차단하고 실패한 파일 예약은 재시도 때까지 보존함.
- Supabase Advisor의 RLS 정책 없음 INFO는 직접 접근을 전부 차단한 서버 전용 구조에 해당. [설명](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).
- 기존 Auth의 ‘유출 비밀번호 자동 검사 비활성’ WARN은 남아 있음. 무료 플랜을 유지하며 변경하지 않았음. [설정·플랜 조건](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- 기존 Python 테스트에서 Starlette의 httpx 연동 폐기 예정 경고가 있으나 34개 테스트는 통과. 현재 Pages 운영 경로는 해당 Python 서버를 사용하지 않음.

재실행: `npm run test:audit` (Python 의존성·한글 폰트·Chromium 필요), 운영 npm 의존성 점검: `npm audit --omit=dev`.
