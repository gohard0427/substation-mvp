# 기존 사진 OCR 검수와 AI 추천

## 현재 상태

제공 ZIP 2개의 62장을 로컬 Tesseract 한국어 OCR로 읽어 **미검수 초안 62개**를 앱 전용 비공개 Supabase에 등록했습니다. 실제 작업 문구·사진·원본 ZIP은 GitHub에 포함하지 않았습니다. OCR 결과에는 오독이 있으므로 자동 정답으로 사용하지 않습니다.

실제 비전 API는 아직 호출하지 않았고, 추천 정확도와 비용을 측정하지 않았습니다. 외부 API 키와 활성화 설정이 없으면 AI 버튼은 비활성입니다. 추천 기능은 선택적 유료 외부 API를 사용하며 웹 호스팅 무료 플랜과 별개입니다.

## 관리자가 할 일

1. 앱에서 **관리자**로 로그인합니다.
2. **기존 사진 OCR 검수·참고 자료**를 펼칩니다.
3. **예시 ZIP 연결**에서 예시1.zip과 예시2.zip을 선택합니다. 일반 작업 업로드와 다른 관리자 전용 입력입니다. 원본 파일 해시로 OCR 초안과 연결하며 서버에는 명판을 가린 사본만 저장합니다.
4. 원본 명판 미리보기와 OCR 원문을 대조해 기기명·작업명·날짜·설비 타입을 수정하고, **검수 완료 → 검수 내용 저장**을 누릅니다. 원본 명판 미리보기는 이 브라우저에서만 표시됩니다. 새로고침 후에는 ZIP을 다시 선택하면 표시되고 이미 연결된 사진은 중복 업로드하지 않습니다.
5. 최소 몇 종류의 작업을 검수한 다음 AI를 연결합니다. 평가용 폴더는 평가용으로 지정하세요. 같은 ZIP·폴더 전체를 함께 분리하며 평가 자료는 추천 검색에 포함하지 않습니다.

검수 전이거나 이미지 연결이 완료되지 않은 참고 사진은 추천에 사용하지 않습니다. 직접 확인한 작업명만 표준 목록에 추가하며 OCR 원문은 별도로 유지합니다. OCR 초안에 없는 신규 참고 ZIP의 자동 OCR 등록 화면은 아직 없으며 아래 오프라인 도구와 관리자 데이터 등록이 필요합니다.

## 외부 AI 연결 — 별도 비용 승인 후

Cloudflare Pages **Production → Variables and secrets**에:

| Type | Name | Value |
|---|---|---|
| Secret | OPENAI_API_KEY | 회사 API 프로젝트 키 |
| Text | AI_ENABLED | true |
| Text | OPENAI_VISION_MODEL | gpt-4.1-mini (기본값) |
| Text | AI_DAILY_LIMIT | 20 (최근 24시간 전체 앱 호출 시도 한도) |

저장 후 재배포합니다. AI_ENABLED를 false로 바꾸고 재배포하면 외부 호출을 끕니다. 결제·보관 정책을 확인하기 전 활성화하지 마세요. API 키를 채팅이나 GitHub에 보내지 않습니다. 웹 구독 요금과 API 사용료는 별개입니다. API 프로젝트에 전용 키를 쓰고 공급자 대시보드에서 사용량도 확인합니다.

요청에 `store:false`를 사용하지만 **공급자의 남용 모니터링 보관까지 0일로 보장하는 옵션은 아닙니다.** 회사의 API 데이터 학습 이용·로그 보관·조직별 보존 조건을 공급자에서 확인해야 합니다. 앱은 공급자의 정책 변경을 자동 판정하지 않습니다.

실패/시간 초과를 포함한 시도를 먼저 DB에 예약해 비용 폭증을 막습니다. 동시 요청과 중복 호출을 제한하고, 완료 결과는 서버에 캐시합니다. `AI_DAILY_LIMIT`은 1~200회 범위이고 기본 20회입니다. 호출 횟수 제한이며 금액 한도는 아닙니다. 실제 입력 이미지/모델에 따라 비용이 달라집니다. 관리자는 검수 화면 아래에서 최근 24시간 호출 시도와 실제 응답 토큰 수를 봅니다. 비용 금액·정답률은 임의로 표시하지 않습니다.

## 작업자 흐름

사진 업로드 → 필요한 설비 정보 입력 → **사진별 AI 추천 요청** → 각 사진의 후보 확인·선택 → 확인 완료 → 명판 생성. AI는 내용을 자동 확정하지 않습니다. PMA 타입 GIS의 코일 저항/PMA 전압 측정은 높은 확신 응답이어도 직접 선택이 필수입니다.

원본을 EXIF 보정하고 기존 명판 위치를 가린 뒤, 최종 명판 합성과 동일한 회전·4:3 레이아웃으로 분석 사본을 만듭니다. 명판을 가리는 과정에서 일부 작업 단서가 줄어들 수 있습니다. 사진별 처리는 한 장씩이며 화면을 닫으면 새 호출은 멈추고 완료된 결과는 복구됩니다. 처리 중인 요청은 최대 대기 시간 동안 예약되므로 즉시 중복 호출하지 않습니다. 대규모 서버 비동기 분석은 미구현입니다.

참고 사례 검색은 명판을 가린 이미지의 실제 픽셀에서 계산한 **색상 히스토그램 48개 + 공간 밝기 16개 특징**으로 3개를 검색합니다. 텍스트 임베딩을 이미지 검색으로 표시하지 않습니다. 이는 초기 저수준 특징 검색이며 의미적 이미지 임베딩/전용 학습 모델이 아닙니다. 외형·배경 변화에 약할 수 있고 실제 사진 평가 전 정확도를 보장하지 않습니다. 같은 폴더에서 작업자가 ‘대상 기기’로 확정한 사진의 설비 정보만 문맥에 추가합니다. 같은 ZIP 전체의 설비가 같다고 가정하지 않습니다.

## 개발자 설치·테스트

신규 전용 DB는 기존 001·002 마이그레이션 다음에 `supabase/schema/ai-reference.sql`을 적용하고, `supabase/schema/private-reference-bucket.sql`로 비공개 `np-reference-private` JPEG 버킷(파일당 1MiB)을 만듭니다. 참고 사진 예약 한도 100MiB와 기존 작업용 700MiB는 별도로 적용됩니다. 표·AI RPC는 service_role 전용이며 브라우저는 서버의 관리자 확인을 통과해야 합니다.

`npm run test:ai`: 실제 PGlite SQL + 모의 Auth/Storage/비전 응답. `npm run test:browser`: 실제 Chromium 명판·회전·마스킹·이미지 특징·검수 UI·ZIP 검사. 실제 OpenAI 호출이나 실제 모바일 환경 검증과 구별합니다.

`python scripts/extract-reference-ocr.py 예시1.zip 예시2.zip --tessdata 한글traineddata폴더 --output 비공개경로/references.json`으로 OCR 초안을 생성합니다. Tesseract와 한국어 traineddata가 필요합니다. 출력에 회사 정보가 포함되므로 공개 저장소에 올리지 않습니다. 현재 도구는 제공 샘플의 측정된 두 명판 프로필에 맞췄으며 다른 디자인에는 좌표 검증이 필요합니다.

정확도 평가는 아직 수행하지 않았습니다. 폴더별 분리·명판 마스킹 후 실제 API를 연결해 1순위/상위3개·설비/작업별·PMA 탐지·실패율·비용을 산출하는 평가 도구는 다음 단계입니다.

공급자 정책 확인: https://developers.openai.com/api/docs/guides/your-data

Supabase 보안 점검에서 신규 표는 RLS 활성·직접 접근 권한 없음이며, 정책 없음 INFO는 서버 전용 설계에 해당합니다. 기존 Auth의 유출 비밀번호 검사 비활성 WARN도 확인됐으며 이번 기능에서 변경하지 않았습니다. 설명: https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection
